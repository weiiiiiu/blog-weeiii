画流程图时，费时间的往往是把文字变成节点、调整连线，再反复改布局。Next AI Draw.io 可以让 AI 先生成图，再由人和 AI 在同一张画布上接着修改，最后留下可编辑的源文件。

这篇笔记来自[挖挖介绍 AI 画图工具的文章](https://mp.weixin.qq.com/s/a5Bm1VeQ40pxkxTX-fHjZw)。原文用手机导航举例，重点演示了生成、局部修改、版本对比和保存；下面补上接入命令，并换成博客发布流程作为练习。

## 工具怎样配合

**AI 助手负责理解需求，MCP 负责连接工具，draw.io 负责承载可编辑的图。** 在浏览器里手动调整后，AI 可以读取当前画布再继续修改。它适合需要多次讨论和调整的流程图、架构图等。[项目介绍](https://github.com/DayuanJiang/next-ai-draw-io)

项目提供网页版、桌面版和 MCP 服务。这里记录 MCP 方式：在已有 AI 对话中提要求，在浏览器中看结果。

## 在 Codex CLI 中接入

先确认电脑能运行 Node.js 和 npx：

```bash
node --version
npx --version
```

安装好 Codex CLI 后，添加名为 `drawio` 的 MCP 服务：

```bash
codex mcp add drawio -- npx @next-ai-drawio/mcp-server@latest
```

查看配置是否出现：

```bash
codex mcp list
```

重新启动 Codex CLI，进入项目后发起绘图请求。工具会返回浏览器预览地址；如果没有自动打开，就手动访问它返回的完整链接。[项目接入说明](https://next-ai-drawio.jiang.jp/en/mcp)

这条命令面向 **Codex CLI**。其他客户端应使用各自的 MCP 配置入口；Codex 的配置方式也可查阅 [OpenAI 的 MCP 文档](https://developers.openai.com/codex/mcp)。

## 先把绘图要求说完整

一个实用的提示词可以交代四件事：**图给谁看、必须包含什么、分支怎样走、布局有什么要求。**

下面是一个博客发布流程的练习提示词：

```text
用 drawio 绘制一张中文流程图，给第一次维护这个博客的人看。

主题：一篇 Markdown 文章怎样发布到线上。

请先阅读仓库配置，再画出这些阶段：
1. 在 content/posts 中编写文章。
2. 检查标题、日期、分类和 Markdown 格式。
3. 本地构建并预览。
4. 提交到 GitHub 的 master 分支。
5. Cloudflare Pages 构建和部署。
6. 打开线上文章，确认正文和首页入口正常。

把“本地准备”和“线上发布”分成两个区域。
本地构建失败时返回编辑；线上构建失败时进入日志排查。
从左向右排列，节点文字简短，判断节点标明成功和失败。
如果仓库实际配置与上述流程不符，先指出差异。
```

第一版先检查流程关系。比如构建失败后回到哪里、部署成功后是否还有验收步骤，都比节点颜色更值得先确认。

## 在当前画布上逐步修改

少量文字可以直接双击节点修改，位置可以拖动调整。需要统一改几个节点时，先在画布中选中它们，再把修改范围说清楚。工具提供读取选区的能力，AI 可以围绕当前选中的图形操作。[选区与编辑能力](https://next-ai-drawio.jiang.jp/en/mcp)

可以这样描述一次局部修改：

```text
读取当前选中的节点。
把这些节点设为浅橙色背景，保留文字和连线关系。
不要调整未选中节点的位置。
修改后检查文字是否溢出，以及箭头是否被遮挡。
```

结构调整和样式调整分开进行会更容易检查。先补充遗漏的步骤，再处理颜色、间距和对齐；每轮只改变一类内容，出现问题时也更容易找到原因。

## 对比版本再恢复

AI 修改会保留版本记录，可以把旧版本与当前画布进行对比，再恢复到需要的版本。[版本功能](https://github.com/DayuanJiang/next-ai-draw-io)

恢复之前，建议先看清要保留的变化。比如上一版布局更好，但这一版修正了某个节点文字，可以要求只恢复布局，而不是把所有修改一起撤销。

## 保存源文件和交付图片

不同文件适合不同用途：

| 格式 | 适合的用途 |
| --- | --- |
| `.drawio` | 保留可编辑源文件，方便以后继续修改 |
| `.png` | 插入文章、文档或演示稿 |
| `.svg` | 需要清晰缩放的矢量图片 |
| `.drawio.svg` | 同时保留 SVG 展示和 draw.io 编辑信息 |

这些格式均在项目的导出支持范围内。跨会话继续编辑时，也可以让 AI 打开已有的 `.drawio` 或 `.drawio.svg` 文件。[导入与导出说明](https://github.com/DayuanJiang/next-ai-draw-io/tree/main/packages/mcp-server#readme)

交付时可以同时保存 `blog-publish.drawio` 和 `blog-publish.svg`：前者用于维护，后者用于展示。浏览器预览依赖本地服务，长期归档和分享应使用导出的文件。

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 新对话里没有 drawio 工具 | 确认 MCP 配置已添加，并重新启动客户端 |
| 预览页面没有更新 | 使用当前会话返回的完整地址，保留链接中的参数 |
| 编辑器内嵌浏览器显示空白 | 用 Chrome 等普通浏览器打开预览地址 |
| 提示没有活动会话 | 让 AI 先启动或恢复绘图会话 |
| 截图或图片导出超时 | 将预览标签页切到前台，再尝试导出 |

具体排查见 [MCP 服务文档](https://github.com/DayuanJiang/next-ai-draw-io/tree/main/packages/mcp-server#troubleshooting)。

## 画完后检查什么

AI 可以减少画框、连线和排版的工作，流程本身仍要逐项核对：

- 每条判断分支是否都有去向，成功和失败是否标反。
- 是否遗漏异常处理、重试或人工确认步骤。
- 箭头方向、节点名称与原始需求是否一致。
- 导出的图片是否完整，源文件是否一并保存。

把流程说清楚、在画布上小步修改、留下可编辑文件，才能让这张图在下一次需求变化时继续用起来。
